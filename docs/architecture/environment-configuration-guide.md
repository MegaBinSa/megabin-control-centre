# Environment Configuration Guide

**Status:** Phase 5B configuration and secret contract

Use `.env.example` only for Local and the two environment example files only as name inventories. Never copy values into tracked files. Run `pnpm env:validate:staging -- --deployment` in deployment and `pnpm env:validate:production` for a non-deploying readiness report.

## GitHub Staging Environment

Secrets: `SUPABASE_ACCESS_TOKEN`, `SUPABASE_DB_PASSWORD`, `SUPABASE_PUBLISHABLE_KEY`, `WEBSITE_ONBOARDING_SECRET`, `COMMUNICATIONS_WEBHOOK_SECRET`, `STAGING_OFFICE_PASSWORD`, `STAGING_DRIVER_PASSWORD`.

Variables: `SUPABASE_PROJECT_REF`, `SUPABASE_URL`, `OFFICE_ORIGIN`, `DRIVER_ORIGIN`, `WEBSITE_ONBOARDING_INTEGRATION_KEY`, `COMMUNICATIONS_TEST_RECIPIENTS`, `STAGING_OFFICE_EMAIL`, `STAGING_DRIVER_EMAIL`, `FRONTEND_DEPLOYMENT_CONFIGURED`. Build timestamps are generated by the workflow, not entered manually.

Supabase Function secrets receive environment/build identity, explicit origins, website signing configuration and capture-mode communications configuration. Provider credentials remain absent. Hosting receives only the publishable Supabase key, URLs, environment and build metadata. A service-role/secret key is forbidden in browser configuration.

Configuration drift is checked by the validator against required names and invariant relationships. It does not display values. The project reference must match hosted Supabase URLs; both frontend origins must be HTTPS, distinct and explicitly allowlisted; wildcard authenticated CORS is rejected; risky automation stays false.
