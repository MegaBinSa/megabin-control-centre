# Office Route Operations Workflow

**Status:** Phase 2C implemented workflow

1. Select a service region/date and load operations.
2. After a Route Version is Published, enter its immutable ID and explicitly hand it off.
3. Review operations by team, lifecycle, staff/vehicle, revisions, acceptance, and start status.
4. Before execution, reassign with the current revision, compatible resources, and a reason.
5. Refresh after conflicts; never edit the Published Route for operational substitutions.

Cancellation and supersession have fixed Office APIs but are not promoted as routine UI actions yet. Live GPS, stop outcomes, and reporting are outside this workflow.
